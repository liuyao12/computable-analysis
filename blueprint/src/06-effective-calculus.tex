\chapter{The FTC Bridge: Effective Calculus}\label{ch:effective-calculus}

This chapter proves the finite bridge promised by
Chapter~\ref{ch:integrals}.  It does not define another integral.  A function
earns an endpoint theorem by supplying explicit interval images, derivative
bounds, partition budgets, and representation edges.

\begin{verbatim}
raw evaluator -> interval regularity -> cell derivative bounds
              -> finite weighted sum -> stabilized raw integral
              -> primitive endpoint difference
\end{verbatim}

The scoped Lean entry point is
\texttt{ComputableAnalysis.EffectiveCalculusFoundation}.  Coverage is by
computational pattern: one representative is proved for each new mechanism;
routine scalar, polynomial, and finite-piece variants are assembled from it.

 \frac{f(g(x+h))-f(g(x))}{g(x+h)-g(x)}

\section{Adaptive application}

A valid input need not converge at the same rate as the function's interval
evaluator.  Output stage \(n\) therefore searches for a sufficiently narrow
input box before evaluation.  Finite prefix intersections make the resulting
image boxes nested.  If two input algorithms represent the same real, their
possibly different selected boxes overlap; a rational point in that overlap
shows that the two applications represent the same output.  Thus one
implementation edge maps to one output edge, with no pairwise registry.

\begin{verbatim}

\section{Application recipe}

A new calculus theorem should expose this chain:

\begin{verbatim}
domain chart -> raw evaluator -> interval regularity
             -> derivative/range boxes -> finite partition sum
             -> shrinking endpoint box -> representation equivalence
\end{verbatim}

Regularity alone does not certify an integral.  A derivative bound, curvature
certificate, or finite piecewise assembly must supply the endpoint
comparison.  If schedules differ, add one raw overlap edge.  If a function has
finitely many pieces, telescope the finite list.  Missing analytic data remain
visible; completeness of standard real numbers is never a fallback.
