\section{Archimedes' Method of Exhaustion}

Archimedes' method of exhaustion computes the area of the unit disk by
trapping it between an inscribed polygon and a circumscribed polygon, then
refining the polygons until the two areas are forced close together.  The
classical presentation starts with a hexagon and repeatedly doubles the number
of sides, producing regular \(6\cdot2^n\)-gons.  That version is geometrically
natural, but its vertices generally have coordinates involving square roots
and other non-rational quantities.  It is therefore not the most transparent
first algorithm for a blueprint whose basic data are rational intervals.

We instead use the rational parametrization of the circle.  Put a vertical
parameter segment from \((1,0)\) to \((1,2)\), and for \(u\in[0,1]\cap\Q\)
let \(L(u)=(1,2u)\).  The line through \((-1,0)\) and \(L(u)\) meets the unit
circle again at
\[
  P(u)=
  \left(
    \frac{1-u^2}{1+u^2},
    \frac{2u}{1+u^2}
  \right).
\]
This is the normalized version of the classical parametrization of
Pythagorean triples: Euclid already knew that triples of the form
\[
  (r^2-s^2,\,2rs,\,r^2+s^2)
\]
satisfy the Pythagorean equation, and dividing by \(r^2+s^2\) gives a rational
point on the unit circle.  Bisection on the vertical parameter segment keeps
all data rational, and the corresponding points \(P(u)\) partition the
quarter-circle.  Polygonal area is then especially convenient: determinants
of rational coordinates are rational, so no square-root subroutine is needed.
Thus the first computation of \(\pi\) in this development is an area
computation, not a circumference computation.

\begin{remark}[Rational circle parametrization]
\label{rem:rational-circle-point}

def circle_point(u):

\end{remark}

\begin{definition}[Circle-area exhaustion algorithm]\label{def:circle-area-stage-algorithm}
\lean{ComputableAnalysis.piCircleArea}
\lean{ComputableAnalysis.circleAreaIncrement}
\lean{ComputableAnalysis.circleAreaDecrement}
\lean{ComputableAnalysis.refineAreaBounds}
\lean{ComputableAnalysis.PiProofs.AreaLoopValidity.areaValid}
\lean{ComputableAnalysis.PiProofs.four_arctanGeom_one_compute_eq_piCircleArea_compute}
\lean{ComputableAnalysis.PiProofs.fourArctanGeomOneValid}
\lean{ComputableAnalysis.PiProofs.four_arctanGeom_one_equiv_piCircleArea}
\lean{ComputableAnalysis.PiProofs.piCircleArea_equiv_four_arctanGeom_one}
\uses{rem:pseudocode-convention}
The loop form of the stage algorithm keeps a current lower bound \(a\), a
current upper bound \(b\), and the list of rational parameter intervals still
being refined.  On one interval \([p,r]\), let \(q=(p+r)/2\).  The lower-bound
increment is the area of the new chord triangle, and the upper-bound decrement
is the tangent triangle removed from the old outer cap:
\[
  \Delta(p,q,r)=
    \frac{2(r-p)(q-p)(r-q)}
      {(1+p^2)(1+q^2)(1+r^2)},
\]
\[
  \nabla(p,q,r)=
    \frac{(r-p)(q-p)(r-q)}
      {(1+pr)(1+pq)(1+qr)}.
\]
The case \(p=0,r=1\) is the quarter circle.  The initial quarter-sector bounds
are \(1/2\le\pi/4\le1\), and the final answer is multiplied by \(4\).
\begin{verbatim}
def piCircleArea(n):
    a, b = 1/2, 1
    intervals = [(0, 1)]

    def increment(p, q, r):
        return (2*(r-p)*(q-p)*(r-q) /
                ((1+p*p)*(1+q*q)*(1+r*r)))

    def decrement(p, q, r):
        return ((r-p)*(q-p)*(r-q) /
                ((1+p*r)*(1+p*q)*(1+q*r)))

    for _ in range(n):
        next_intervals = []
        for p, r in intervals:
            q = (p + r) / 2
            a = a + increment(p, q, r)
            b = b - decrement(p, q, r)
            next_intervals.append((p, q))
            next_intervals.append((q, r))
        intervals = next_intervals

    return [4*a, 4*b]
\end{verbatim}
Every operation in this pseudocode is a rational operation.  The returned pair
for \code{piCircleArea} is meant to be the first raw interval algorithm for
\(\pi\): the lower endpoint is the area of the refined inscribed rational
polygon, and the upper endpoint is the area of the corresponding refined outer
tangent polygon.  In Lean this increment/decrement loop is the single public
\code{piCircleArea} definition.
\end{definition}

\section{Sector Area, Arctangent, and Normalized Angles}

The second algorithm is not a new idea, but the same exhaustion procedure with
a moving endpoint.  For \(0\le x\le1\), take the point \(L(x)=(1,2x)\) on the
vertical parameter segment and project it from \((-1,0)\) to the unit-circle
point \(P(x)\).  Refining the parameter interval \([0,x]\) gives rational
inner and outer polygonal bounds for the sector from \(P(0)=(1,0)\) to
\(P(x)\).  The geometric angle of this sector is \(2\arctan(x)\); since a unit
sector has area equal to half its angle, the area computed by the algorithm is
\(\arctan(x)\).  Thus \(x=1\) is exactly the quarter-circle case, and
\[
  4\arctan_{\mathrm{geom}}(1)\sim \pi_{\mathrm{area}}.
\]

\begin{definition}[Geometric arctangent area algorithm]
\label{def:geometric-arctan}
\label{def:arctan-area-stage-algorithm}
\lean{ComputableAnalysis.ArctanGeometry.arctanGeom}
\lean{ComputableAnalysis.ArctanGeometry.arctanGeom_one_compute_eq}
\lean{ComputableAnalysis.ArctanGeometry.arctanAreaIncrement}
\lean{ComputableAnalysis.ArctanGeometry.arctanAreaDecrement}
\lean{ComputableAnalysis.ArctanGeometry.arctanGeom_nonneg_compute_eq}
\lean{ComputableAnalysis.ArctanGeometry.PiAreaCompatibility}
\lean{ComputableAnalysis.ArctanGeometry.piAreaCompatibility}
\uses{def:circle-area-stage-algorithm,rem:rational-circle-point,rem:pseudocode-convention}
For \(0\le x\le1\), the arctangent algorithm starts with the chord-triangle
lower bound \(x/(1+x^2)\) and the tangent-triangle upper bound \(x\).  It then
bisects the current rational parameter intervals, using exactly the same
increment and decrement formulas as \code{piCircleArea}.
\begin{verbatim}
def arctanGeom(x, n):
    a = x / (1 + x*x)
    b = x
    intervals = [(0, x)]

    def increment(p, q, r):
        return (2*(r-p)*(q-p)*(r-q) /
                ((1+p*p)*(1+q*q)*(1+r*r)))

    def decrement(p, q, r):
        return ((r-p)*(q-p)*(r-q) /
                ((1+p*r)*(1+p*q)*(1+q*r)))

    for _ in range(n):
        next_intervals = []
        for p, r in intervals:
            q = (p + r) / 2
            a = a + increment(p, q, r)
            b = b - decrement(p, q, r)
            next_intervals.append((p, q))
            next_intervals.append((q, r))
        intervals = next_intervals

    return [a, b]
\end{verbatim}
The algorithm is packaged as its own raw function, not as a definitional
alias of \code{piCircleArea}.  The special case \(x=1\) is related to
\code{piCircleArea} by a theorem, which is the right proof obligation for the
geometric identity \(\pi=4\arctan_{\mathrm{geom}}(1)\).
\end{definition}

\begin{theorem}[Sector-area density]
\label{thm:sector-area-density}
\lean{ComputableAnalysis.RationalCircle.Stage.pointDerivative}
\lean{ComputableAnalysis.RationalCircle.Stage.sectorAreaSpeed}
\lean{ComputableAnalysis.RationalCircle.Stage.sectorAreaDensity}
\lean{ComputableAnalysis.RationalCircle.Stage.sectorAreaSpeed_eq_two_over_one_plus_square}
\lean{ComputableAnalysis.RationalCircle.Stage.sectorAreaDensity_eq_one_over_one_plus_square}
\uses{rem:rational-circle-point}
\leanok
For the rational parametrization \(P(u)=(X(u),Y(u))\), the exact derivative is
\[
  P'(u)=
  \left(
    \frac{-4u}{(1+u^2)^2},
    \frac{2(1-u^2)}{(1+u^2)^2}
  \right).
\]
The signed area speed of the sector is
\[
  X(u)Y'(u)-Y(u)X'(u)=\frac{2}{1+u^2}.
\]
Therefore the unit-sector area density is
\[
  \frac12\bigl(X(u)Y'(u)-Y(u)X'(u)\bigr)
  =
  \frac{1}{1+u^2}.
\]
This explains the kernel used in Chapter~\ref{ch:integrals}.  The later
comparison with the integral arctangent is carried by finite rational
inequalities between rectangle sums and the same geometric sector sums, rather
than by taking area or derivative facts as primitives.
\end{theorem}

\begin{theorem}[Geometric arctangent gives the area definition of pi]
\label{thm:geometric-arctan-one-area-pi}
\lean{ComputableAnalysis.PiProofs.fourArctanGeomOneValid}
\lean{ComputableAnalysis.PiProofs.arctanGeomOneValid}
\lean{ComputableAnalysis.PiProofs.four_arctanGeom_one_equiv_piCircleArea}
\lean{ComputableAnalysis.PiProofs.piCircleArea_equiv_four_arctanGeom_one}
\uses{def:circle-area-stage-algorithm,def:geometric-arctan}
The geometric sector-area arctangent satisfies
\[
  4\arctan_{\mathrm{geom}}(1)\sim \pi_{\mathrm{area}}.
\]
Lean proves this by transporting the verified \code{piCircleArea} interval
algorithm across the same-stage equality with \code{4 * arctanGeom(1)}.
The positive-scaling converse in \cref{prop:raw-arithmetic-valid} then also
certifies the unscaled raw real \code{arctanGeom(1)}.
\end{theorem}

\begin{theorem}[Arctangent validity and monotonicity]
\label{thm:arctan-area-valid-monotone}
\lean{ComputableAnalysis.ArctanGeometry.positiveLoopRaw_valid_on_unit}
\lean{ComputableAnalysis.ArctanGeometry.arctanGeom_valid_on_unit}
\lean{ComputableAnalysis.ArctanGeometry.arctanGeom_valid_on_powerSeriesDomain}
\uses{def:arctan-area-stage-algorithm,def:raw-real-order}
For each rational \(x\in[0,1]\), \code{arctanGeom(x,n)} is a valid raw real:
the geometric lower and upper sector bounds are ordered, nested, and shrinking.
This has also been packaged on the symmetric power-series domain \(|x|\le1\),
using oddness to reduce the negative branch to the positive loop.
Moreover, the resulting function should be monotone: if
\(0\le x\le y\le1\), then
\[
  \arctan_{\mathrm{geom}}(x)\le \arctan_{\mathrm{geom}}(y).
\]
The validity proof is finite: endpoint monotonicity comes from nonnegative
increment/decrement triangles, while shrinking follows because the geometric
intervals sit inside the already verified rectangle-sum intervals.  Strict
monotonicity on apart rational inputs should follow from the positive area of
the additional sector between \(P(x)\) and \(P(y)\).
\end{theorem}

\begin{definition}[Normalized quarter-turns as angles]

\begin{definition}[Monotone inverse arctangent interface]
\label{def:inverse-arctan-interface}
{\scriptsize
\par\noindent
\lean{ComputableAnalysis.RationalCircle.GeometricTrig.firstOctantBranch}\par
\lean{ComputableAnalysis.IntegralIdentities.ArctanInverseBisection}\par
\lean{ComputableAnalysis.IntegralIdentities.ArctanInverseBisection.tangentRaw}
}
\uses{def:geometric-arctan,def:quarter-turn-angle,def:qbox,thm:constructive-inverse-function}
The inverse-arctangent step is the first trigonometric consumer of the
constructive inverse-function theorem.  The bounded slope branch is the first
octant \(0\le t\le1/2\), whose angles lie in \([0,\pi/4]\); the second octant
is then obtained by reciprocal/complement reduction.  Thus the search never
pretends that tangent is bounded at a quarter turn.

For a recovered slope \(u\in[0,1]\), the rational circle chart
\[
  P(u)=\left(\frac{1-u^2}{1+u^2},\frac{2u}{1+u^2}\right)
\]
supplies the intended first-octant point.  The two coordinate projections are
therefore the planned definitions of \(\cos(t\pi/2)\) and
\(\sin(t\pi/2)\).  This keeps the dependency direction explicit: geometric
arctangent is inverted first, then the same rational chart that drove the
circle exhaustion defines sine and cosine.

Lean now has a checked bridge \code{ArctanInverseBisection}.  It requires an
\code{InvertibleFunctionOnInterval} whose forward function is certified equal
to \code{arctanGeomOnUnit}, a valid range-enclosed target for every first-octant
quarter turn, and an \code{InverseBisectionSearch} for each target.  From this
data it constructs the actual partial raw tangent function
\code{tangentRaw}; its output boxes are valid, remain in the unit slope
interval, and their forward interval evaluations overlap the target boxes at
every stage.  The still-open analytic work is to construct this package for
the geometric arctangent, not to postulate inverse laws.  The older
\code{ArctanInverseConstruction} remains a downstream special-value contract.
The checked bridge asks for:
\begin{enumerate}
\item the actual geometric arctangent branch and its interval inverse data,
\item a valid target, with explicit endpoint range enclosure, for each angle,
\item a bisection search whose output remains in the source interval and
  overlaps the forward target evaluation, and
\item an equivalence between each target and the selected quarter-turn
  representative \(t\pi/2\).
\end{enumerate}
Constructing the interval evaluation of \(P(u)\) for the recovered raw slope,
and then extending from the first octant by the stated reductions, is the next
formal trigonometric step.  The bridge already fixes its required inverse data
rather than assuming trigonometric inverse laws.
\end{definition}

\begin{definition}[Inverse arctangent search]
\label{def:inverse-arctan-search}
\uses{def:arctan-area-stage-algorithm,thm:arctan-area-valid-monotone}
For an angle parameter \(t\) interpreted as \(t\pi/2\) and known on the
principal first-octant branch \(0\le t\le 1/2\), define its tangent parameter
\(u\in[0,1]\) by bisection against the monotone arctangent algorithm.
\begin{verbatim}
def inverse_arctan(t, n):
    lo, hi = 0, 1
    for i in range(n):
        m = (lo + hi) / 2
        am = arctanGeom(m, n+i)
        if am.hi < t*pi/2:
            lo = m
        elif t*pi/2 < am.lo:
            hi = m
        else:
            lo, hi = lo, hi
    return [lo, hi]
\end{verbatim}
The stage used for \code{arctanGeom(m, n+i)} is intentionally allowed to
increase inside the search: the comparison must be refined until it certifies
which side of \(m\) contains the inverse, or else safely keeps the current
bracket.  The output is a rational interval for \(u=\tan(t\pi/2)\).
\end{definition}

\begin{definition}[Sine and cosine from inverse arctangent]
\label{def:sin-cos-from-inverse-arctan}
\uses{def:inverse-arctan-search,rem:rational-circle-point}
On the first octant, compute an interval for \(u=\tan(t\pi/2)\) by
\cref{def:inverse-arctan-search} and then evaluate the rational circle
coordinates
\[
  \cos(t\pi/2)=\frac{1-u^2}{1+u^2},
  \qquad
  \sin(t\pi/2)=\frac{2u}{1+u^2}.
\]
Interval evaluation of these rational formulas gives boxes for sine and
cosine without ever computing a square root.  Quadrant, sign, and reciprocal
reductions extend the construction to the full normalized interval \([0,1]\)
once \(\pi/4=\arctan_{\mathrm{geom}}(1)\) and the endpoint at \(t=1\) have
been identified.
\end{definition}

\begin{definition}[Sine and cosine from a circle-point algorithm]
\label{def:sin-cos-from-circle-point}
\lean{ComputableAnalysis.RationalCircle.GeometricTrig.FunctionRawConstruction}
\uses{def:inverse-arctan-interface}
After inverse arctangent has located the point on the oriented unit circle, the
trigonometric functions are projections:
\[
  \cos(t\pi/2)=X(t),\qquad \sin(t\pi/2)=Y(t).
\]
Lean packages this as a complex-valued point algorithm plus real-coordinate
projection functions \code{cosFunctionRawOfPoint} and
\code{sinFunctionRawOfPoint}.  The first identity theorem for these functions
should be the unit-circle law; all addition, parity, double-angle, reciprocal,
and tangent identities are then consequences of the circle law and point
multiplication.
\end{definition}

\begin{remark}[Dyadic subdivision of a rational interval]
\label{rem:dyadic-rational-circle-stages}
\lean{ComputableAnalysis.RationalCircle.dyadicStage}
\uses{rem:rational-circle-point,rem:pseudocode-convention}
Start with a rational interval \([x,y]\).  Bisect every current interval
\(n\) times, and then map the resulting rational parameters to the circle by
the rational parametrization \(P\).  Equivalently, the rational parameters
after \(n\) bisections are
\[
  x+\frac{k}{2^n}(y-x),
  \qquad 0\le k\le 2^n.
\]
\begin{verbatim}
def dyadic_subdivision(x, y, n):
    s = [x, y]
    for _ in range(n):
        t = []
        for i in range(len(s) - 1):
            a = s[i]
            b = s[i + 1]
            t.append(a)
            t.append((a + b) / 2)
        t.append(s[-1])
        s = t
    return s

def circle_subdivision(x, y, n):
    return [circle_point(u) for u in dyadic_subdivision(x, y, n)]

def circle_stage(n):
    return circle_subdivision(0, 1, n)
\end{verbatim}
\end{remark}

For the full circle it is better to treat the parameter line projectively.
Lean now has a homogeneous rational parameter \((a:b)\), with finite value
\(a/b\) when \(b\ne0\) and a formal point \(\infty=(1:0)\) when \(b=0\).
The circle map is polynomial-rational in the homogeneous coordinates:
\[
  (a:b)\longmapsto
  \left(
    \frac{b^2-a^2}{a^2+b^2},
    \frac{2ab}{a^2+b^2}
  \right).
\]
For \(b\ne0\) this agrees with the earlier affine parametrization
\(P(a/b)\), while \(\infty\) maps to \((-1,0)\).  This gives the compactified
parameter circle needed for full-circle constructions and for later
``whole real line'' substitutions, where an endpoint at infinity should be a
formal object rather than a special case.  The same projective line is now
also the codomain of tangent.  Lean separates these two infinities: the
projective parameter \(\infty\) is the point \((-1,0)\), whereas the tangent of
the quarter-turn point is the formal projective value \(\infty\).  In the
affine quarter-circle chart this is stated as \(\tan(1)=\infty\), with a
compatibility theorem saying that \(\tan(u)\) is the finite rational quotient
whenever \(\cos(u)\ne0\).  The negation, subtraction, and
quarter-complement identities are therefore stated projectively, so that zero
and infinity are exchanged without adding endpoint exceptions.
\[
  -(-x)=x,\qquad (x^{-1})^{-1}=x,\qquad (-x)^{-1}=-(x^{-1}),
\]
\[
  0\oplus x=x=x\oplus0,\qquad
  (x\oplus y)\oplus z=x\oplus(y\oplus z),
\]
\[
  x\oplus(-x)=(-x)\oplus x=0,\qquad x\ominus x=0,
\]
\[
  x\ominus0=x,\qquad 0\ominus x=-x,\qquad
  x\ominus(-y)=x\oplus y,
\]
\[
  (-x)\ominus y=-(x\oplus y),
\]
\[
  (-x)\ominus(-y)=-(x\ominus y),\qquad
  y\ominus x=-(x\ominus y),
\]
\[
  (x\oplus y)\ominus y=x,\qquad
  (x\ominus y)\oplus y=x.
\]
\[
  2(-x)=-(2x),\qquad
  (-x)\oplus(-y)=-(x\oplus y).
\]
The concrete tangent-addition chart formulas are also stated without deleting
the exceptional denominator cases:
\[
  x\oplus y=[x+y:1-xy],\qquad
  x\oplus\infty=\infty\oplus x=[1:-x],
\]
\[
  \infty\oplus\infty=0,\qquad
  2x=[2x:1-x^2],\qquad 2\infty=0.
\]
Likewise subtraction has the projective chart formulas
\[
  x\ominus y=[x-y:1+xy],\qquad
  x\ominus\infty=[1:-x],\qquad
  \infty\ominus x=[1:x],
\]
\[
  \infty\ominus\infty=0.
\]

The circle and trigonometric constructions below use the dyadic
rational-parameter refinements already described above, while the geometric
arctangent keeps its own dynamic sector subdivision.
\end{remark}

\begin{remark}[What bisection refinement means]
\label{rem:dyadic-rational-circle-refinement}
\lean{ComputableAnalysis.RationalCircle.Trigonometry.dyadic_point_refineIndex}
\uses{rem:dyadic-rational-circle-stages}
There is no separate abstract definition of refinement being used here.  The
concrete fact is just that one more bisection keeps every old parameter and
inserts one midpoint between adjacent old parameters.  Thus, after mapping to
the circle, the even-indexed points in the next list are the old points:
\[
  C_{n+1,2k}=C_{n,k}.
\]
The odd indices are the new rational circle points coming from the inserted
midpoints.  Lean records this concrete bookkeeping statement as
\code{ComputableAnalysis.RationalCircle.Trigonometry.dyadic\_point\_refineIndex}.
\end{remark}

\section{Finite Area and Circumference Certificates}

\begin{definition}[Rational triangle area]\label{def:rational-triangle-area}
\uses{rem:pseudocode-convention}
A rational triangle is a triangle whose vertices have rational coordinates.
Its area is rational, because it is computed by the determinant formula:
\begin{verbatim}
def sub(p, q):
    return Point(p.x - q.x, p.y - q.y)

def cross(p, q):
    return p.x*q.y - p.y*q.x

def triangle_area(p, q, r):
    return abs(cross(sub(q, p), sub(r, p)) / 2)
\end{verbatim}
Thus every line in the algorithm is a rational operation, followed only by
the absolute value on \(\Q\).  This determinant calculation is the finite
geometric fact packaged by the incremental area corrections in
\cref{def:circle-area-stage-algorithm}.
\end{definition}

\begin{definition}[Circumference stage algorithm]\label{def:circle-circumference-stage-algorithm}
\lean{ComputableAnalysis.piCircumference}
\uses{def:circle-area-stage-algorithm}
The circumference algorithm uses the same inner and outer rational boundaries,
but replaces polygonal area by path length.  The square-root subroutine is
therefore part of the proof interface: its stage choices must leave enough
room for the finite chord and tangent inequalities to close.  In this
definition, the function named \code{pi} is the circumference algorithm for
pi.
\begin{verbatim}
def pi(n):
    inner, outer = circle_boundaries(n)
    inner_len = path_length_interval(inner, 2**n)
    outer_len = path_length_interval(outer, 2**n)
    return [(4*inner_len.lo)/2, (4*outer_len.hi)/2]
\end{verbatim}
\end{definition}

\begin{theorem}[Law of cosines and the equilateral value]
\label{thm:law-of-cosines-equilateral}
\lean{ComputableAnalysis.RationalCircle.Stage.segmentNormSq_law_of_cosines}

For rational coordinate points \(p,q\), the squared chord length satisfies the
coordinate law of cosines
\[
  \|q-p\|^2=\|p\|^2+\|q\|^2-2(p\cdot q).
\]

them also has squared length \(1\), then \(p\cdot q=1/2\).  This is the
formalized equilateral-triangle core behind the familiar

actual normalized-angle statement for \(\sin_C(1/3)\) still requires the
angle-to-circle-point construction to identify the one-third input with the
equilateral chord.
\end{theorem}

\begin{verbatim}
def geometric_point_stage(t, n):
    t0, transform = reduce_period_quadrant_and_sign(t)
    u = inverse_arctan(t0, n)
    box = interval_eval(lambda t: Point((1-t*t)/(1+t*t), 2*t/(1+t*t)), u)
    return apply_octant_transform(transform, box)
\end{verbatim}
Here each helper is a finite rational procedure: period and octant reduction
uses the area definition of \(\pi\), inverse search uses monotonicity of
\(\arctan\), interval evaluation uses rational formulas, and the final
transform only changes signs and swaps coordinates.  The algorithm may be
refactored internally, but its public output should be a single point raw
function.

Let
\[
  P(u)\cdot P(v)
  =
  (P(u)_xP(v)_x-P(u)_yP(v)_y,\,
   P(u)_xP(v)_y+P(u)_yP(v)_x)
\]
be multiplication of unit-circle points.  Lean now proves the point-level
group laws for this operation: exact norm multiplication, commutativity,
associativity, left and right identity for \((1,0)\), and the conjugate inverse
law on unit points.  Lean also proves the denominator-cleared stereographic
chart-change numerators:
\[
  ((1+u^2)(1+v^2))\,(P(u)P(v))_x
    =(1-uv)^2-(u+v)^2,
\]
\[
  ((1+u^2)(1+v^2))\,(P(u)P(v))_y
    =2(u+v)(1-uv),
\]
together with
\[
  (1-uv)^2+(u+v)^2=(1+u^2)(1+v^2).
\]
Lean now also carries out the normalization division: when \(1-uv\ne0\), the
composed point is exactly
\[
  P(u)\cdot P(v)=P\!\left(\frac{u+v}{1-uv}\right).
\]
The missing-point case \(1-uv=0\) is the expected projective chart transition.
\end{theorem}

\begin{theorem}[Projected addition formulas]
\label{thm:geometric-addition-formulas}
\uses{def:geometric-trig-functionraw-construction,thm:rational-circle-group-law}
Once the point raw function is proved compatible with circle multiplication,
the projected functions satisfy
\[
  \cos_C(a+b)=\cos_C(a)\cos_C(b)-\sin_C(a)\sin_C(b),
\]
\[
  \sin_C(a+b)=\sin_C(a)\cos_C(b)+\cos_C(a)\sin_C(b).
\]
The proof should first be finite and rational on circle boxes, then lifted to
the raw functions by validity and equivalence of the coordinate projections.
\end{theorem}

\begin{theorem}[Standard geometric trigonometric identities]
\label{thm:geometric-trig-identities}
\uses{thm:geometric-addition-formulas,thm:rational-circle-basic-identities}
The final identity package for this chapter contains all the usual
trigonometric identities: the Pythagorean identities
\[
  \sin_C^2 x+\cos_C^2 x=1,\quad
  1+\tan_C^2 x=\sec_C^2 x,\quad
  1+\cot_C^2 x=\csc_C^2 x,
\]
addition and subtraction formulas, parity formulas, double-angle formulas,
half-angle formulas, cofunction formulas, reciprocal and quotient formulas,
and period formulas.  Each identity should be proved from the circle point
construction and its algebra, not by importing another trigonometric
representation.
\end{theorem}

\section{Formalization Order}

\begin{enumerate}
  \item Formalize the rational parametrization of the circle, including its
  Pythagorean-triple origin, dyadic refinement, determinant area formulas, and
  the incremental inner and outer corrections.

  \item Prove validity of the area-first \(\pi\) algorithm and then formalize
  the analogous \(\arctan(x)\) algorithm on \([0,1]\): ordered bounds,
  nesting, convergence, and monotonicity.

  \item Invert \(\arctan\) by certified bisection.  This produces the tangent
  parameter \(u\) for angles in the first octant using only rational interval
  comparisons.

  \item Define sine and cosine by evaluating the rational parametrization at
  the inverse-arctangent parameter.  Extend by octant, quadrant, and period
  transformations, still avoiding square roots.

  \item Define the remaining trigonometric functions as partial quotient or
  reciprocal raw functions with explicit apartness domains.

  \item Prove all usual trigonometric identities for the projected algorithms.
  The main proof inputs are the unit-circle law, circle multiplication, the
  arctangent inverse specification, and the correctness of period and quadrant
  reduction.

  \item Put comparison with any other representation in a later comparison
  chapter or file.  That later stage can import the other definitions it
  needs; this chapter should not depend on them.
\end{enumerate}

The next chapter abstracts the same finite pattern.  Instead of circle-sector
fans, it starts with a monotone rational function on a rational interval,
forms dyadic lower and upper sums, and proves that these sums define the
corresponding definite integral as a raw real.  The arctangent computation in
this chapter is the motivating example: it is the integral of the monotone
kernel \(1/(1+x^2)\), but here it has first been presented in geometric
polygonal form.
