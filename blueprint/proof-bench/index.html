What these measurements can establish
For each matched statement, all proof parameters, hypotheses, and conclusions are checked for definitional equality. The measured set follows references in stored declaration types and bodies, not import lists. The two native routes must remain Mathlib-free; every route must avoid calling its alternative and have no transitive sorryAx.
A small final term may hide a large library. Conversely, broad Mathlib machinery is reusable and should not be charged from scratch for each theorem. The statement-prerequisite and shared-prerequisite views make the assumed baseline explicit; neither makes it mathematically free. This benchmark's target programs are native, so Mathlib bears the separately reported representation-bridge cost.
Tree size is sensitive to repeated subexpressions. Distinct-subexpression counts deduplicate within one stored body, then sum once per declaration. They do not deduplicate across bodies or unfold named constants. Numeric literals and native-computation certificates remain atomic, not expanded arithmetic proofs. Axiom details are available for each route.
Source lines are only a formatting-dependent diagnostic. Counts union available declaration ranges, excluding blank lines and comments, with unmapped declarations reported. Kernel verification, tactic elaboration, import time, numerical execution time, and mathematical conceptual complexity are different costs. This page supplies no invented timing measurements.
A Mathlib-real dependency is not a count of completeness uses. The native foundation can avoid the completed real type while still using ordinary Lean axioms or native-computation assumptions. Compare actual scope, quantified domains, effectiveness, trust, and theorem reuse alongside these sizes.
