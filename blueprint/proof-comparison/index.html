Reading the comparison correctly

Local cost, total cost, and shared foundations

The final theorem is only the last step. “Project closure” includes the root and every transitively referenced project declaration, including compiler-generated helpers. Each declaration is counted once. “Exclusive” means it does not occur in the other proof’s closure; it is not a measure of mathematical independence from the common foundations. The shared arctangent, rational-circle, interval, and arithmetic infrastructure is visible rather than charged twice as new work.

Proof trees versus structural sharing

Tree size counts Lean.Expr constructor occurrences with multiplicity, including implicit arguments, local binder types, and metadata; references to named constants are not unfolded. Distinct-subexpression size deduplicates structurally identical subexpressions within each stored body. Closure totals sum these sizes once per declaration, but do not deduplicate across declaration bodies. Neither number measures mathematical elegance or proof discovery difficulty. Native-computation certificates remain atomic references, not expanded arithmetic proofs.

Actual dependencies, contracted paths, and companion results

The exporter reads constants referenced in both stored types and bodies, including opaque theorem bodies. The overview contracts paths through hidden nodes and removes redundant transitive edges. Every overview edge has an inspectable witness in the full reference graph; it is not a claim of a direct call. The declaration view shows direct reference edges and distinguishes body references from type-only references.

The computed sine derivative is a companion consequence of the same concavity and secant data. Its validity theorem is not itself a premise referenced by either final integral proof. Selecting “Show derivative consequences” displays these extra results separately, without adding them to either proof’s cost.

Source lines and kernel timing

Source-line totals use the union of Lean-reported declaration ranges, excluding blank lines and nested comments. Overlapping ranges are counted once; synthetic declarations without ranges add no source lines. Counts depend on formatting.

Kernel timing synchronously checks only the final stored proof and compares its inferred type with the declared type, with all dependencies already loaded. Eleven trials follow a discarded warmup. It excludes imports, tactic elaboration, and recursively rechecking the prerequisite library. These small timings are environment-dependent, not end-to-end build benchmarks.

Verification and reproducibility

The build runs the existing two-proof audit, compares the complete theorem types by definitional equality, checks forbidden transitive dependencies, and checks for sorryAx. The comparison exporter is tooling, not part of the mathematical foundation. Existing native-computation and standard Lean axioms remain visible in each proof’s trust report.
